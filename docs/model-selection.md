# 算力端手动选模

电脑和手机使用同一套算力端入口：在页面“设置”中展开“模型选择 · 本机”，选择模型后点击“应用选择”。需重新编译安装算力端 HAP；聊天端无需为此修改。

- 选择文字模型（如 Qwen2.5-7B）：本机只执行文字任务，不上报图片能力。
- 选择私有 VL 模型（如 Qwen2.5-VL-3B）：本机只执行带图片的任务。当前 SDK 的 `qwen2vl_chat` 要求非空图片，不能用它执行纯文本。
- “自动（按请求选择）”保留原来的文字/图片分流。该模式展示所有启用的模型，避免把排序第一的目录误当成实际执行模型。
- 仅列出 `files/models/` 下就绪的模型。Pro 已停用的 VL 权重位于 `files/disabled-models/`，不会出现在选项中。
- 设置保存在应用私有目录 `files/model-selection.json`。重启后保留；选定模型缺失时会报不可用，不会悄悄切换到别的模型。

切换会清理空闲 GEWU 会话并释放空闲 VL 权重，然后重新扫描所选 VL 模型；本机仍有推理请求或原生清理任务时不能切换。切换成功会立即向已连接的聊天端和其他算力端更新模型、能力和档位。两条调度链路都将旧协议的空 `needs` 视为文字请求，避免派给只启用 VL 的设备。

界面和设置不绑定设备型号，沿用工程已有的 `phone`、`2in1` 目标。模型是否能推理受设备、运行库和权限限制。当前 VL 固定走应用内 SDK，旧文件队列辅助进程只保留作历史诊断工具；不需要通过 HDC 启动旧 worker。特定调试设备所需的临时访问配置见 [VL 应用内直连](vl-direct-mode.md)。

验证覆盖模型选择持久化、任务类型隔离、失效模型处理、设备展示、调度、忙碌锁、近场停用后的设置刷新和界面草稿保留；相关回归测试通过。2026-10-16 已通过 SDK `default@CompileArkTS` 编译检查，未打包、签名或安装新版 HAP，尚未进行手机和电脑的安装实测。
