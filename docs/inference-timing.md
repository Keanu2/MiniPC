# 推理输出与计时

文本 GEWU 请求默认使用 `stream:true`。`LocalChat` 逐段转发非空文本，只有明确的 `finish_reason` 才结束流；空分片不设置首字时间。流未结束就断开时返回中断错误，不把已有片段冒充完整答案。显式 `ChatStartOptions.stream=false` 保留单次完整响应兼容路径。

## 输出方式设置

算力端“设置 → 输出方式 · 本机”可选择“流式输出（逐段显示）”或“非流式输出（完整返回）”，点击“保存输出方式”生效。电脑和手机使用同一设置入口，默认流式。配置独立保存在本机 `filesDir/inference-output.json`，重启后保留，不随模型切换改变；多台算力设备分别设置。

每次推理开始时读取并固定输出模式，保存只影响后续请求，不改变正在执行的请求。文字 GEWU 请求将选择传给引擎的 `stream` 参数；VL SDK 内部仍逐段生成，选择非流式时桥接层等待生成完成再一次性返回。两种模式均上报实际交付的输出方式，非流式不会标成首字计时。Agent 正式答案仍遵循末尾所述的校验和展示约束。

设置回归覆盖默认值、损坏配置、跨实例读取、保存失败保留旧值、推理中切换、文字请求显式覆盖、VL 完整返回与错误处理，以及设置界面的草稿和重试。此次仅修改源码并执行 Node 回归检查，HAP 由用户编译和上机验证。

## 界面含义

- **首字**：已声明流式输出的请求，应用第一次收到非空文本的等待时间。本机文本链路优先使用原生回调时捕获的、相对本次请求开始的单调时钟时差，避免同一次 ArkTS 轮询把不同回调记成同一时间。旧桥接或远端链路缺少本地回调时间时使用本机接收时钟。GEWU 可能一次返回多个 token，不能将首段回调等同于 NPU 内部逐 token 的精确计时。
- **首次返回**：非流式请求或未声明输出模式的旧对端，首次收到答案的时间。运行信息将首字等待标为“未采集”。不通过“首次返回”等于“完成时间”来猜测请求是否流式。
- **本轮请求 / 任务耗时**：保留原有端到端口径；包含相应范围内的等待、加载、推理、回调和传输。多个并行调用不能直接相加作为任务耗时。
- **引擎上报统计**：仅在运行信息中展示 GEWU 的 `model_load_latency`、`prefill_latency`、`decode_latency`（毫秒）以及输入、输出 token 数。未上报的字段不伪造，不将它们相加推算首字时间。
- **Prefill / Decode 速度**：在每次模型调用的运行信息中显示，分别按 `promptTokens × 1000 / prefillMs` 和 `completionTokens × 1000 / decodeMs` 计算，单位 `token/s`，保留两位小数。使用引擎上报的原始统计精度，不使用字符数、分片数或端到端耗时；也不自行扣减首 token。缺少对应统计、阶段耗时为零或无效时显示“未采集”，有效零 token 显示 `0.00 token/s`，正数不足 `0.01` 显示 `<0.01 token/s`。流式与非流式口径一致，多轮及多设备分别展示，不合并成任务整体速度。

单轮推理任务卡和详情保留毫秒精度，以三位小数秒显示，如 `3.603s` 与 `3.648s`。端到端任务汇总保留原紧凑显示。运行信息另外保留原生首段、末段等待的整数毫秒值，以及非空输出分片数。

短回答如果确实只产生一个非空分片，完成后显示“首段”，并说明首段与末段同批返回、逐 token 首字时间未采集。不用延迟或模拟逐字动画制造差异，不保证两个本来相同的实测时刻变成不同数值。原生时间通过请求时长传递，只有同一设备的本地任务将其映射到本地任务时轴，跨设备不会直接传递或相减墙上时钟。

输出模式和引擎统计使用可选的 `metrics` 字段透传：本机任务、普通聊天的算力设备转发、Agent 的 `infer.delta` / `infer.done` 和协调端任务详情共享相同结构。协议版本不变，缺少新字段的旧对端仍可通信；不跨设备相减墙上时钟。

| 模型 | 首个非空回调 | 最终回调 | 回调数 | 拼接结果 |
| --- | ---: | ---: | ---: | --- |
| Qwen3.5-9B | 2246 ms | 6238 ms | 6 | 你好，世界。今天阳光很好。 |
| Qwen2.5-7B | 4633 ms | 6054 ms | 6 | 你好，世界。今天阳光很好。 |

两次 create、submit、destroy 均成功，中间分片 `finish_reason=null`，最终分片 `finish_reason=stop`。这是流式能力和中文完整性检查，不是两个模型的性能基准；模型加载状态和输入配置会影响数值。

原始诊断源码、日志和拼接校验程序保存在 `.hvigor/ttft-stream-2026-10-20/`。设备临时目录的权重使用硬链接供路径白名单检查，未复制或改写原始权重；测试完成后删除测试链接。

代码回归覆盖：中间分片不提前完成、空分片、空文本结束帧、缺失结束标记、后到回调、非流式兼容、统计值校验、多设备转发，以及未知输出模式不冒充首字计时。

首次流式修改曾生成算力端未签名 HAP；随后按用户“我来编译验证，只修改代码”的要求，原生时间戳、毫秒精度和单分片说明等后续修改未重新编译或安装。此前输出目录的 HAP 不代表当前最新源码。聊天端仅同步可选统计字段的协议定义和校验；旧聊天端仍能接收文本输出。

普通聊天端原本已在 `onDelta` 中更新答案气泡，开启算力端流式后会逐段显示。Agent 的模型响应包含 Plan/Action 等协议内容，正式答案气泡仍等待工具执行和最终答案校验；这是独立的展示约束。每轮模型输出仍可在算力端推理详情中流式查看，不把未经校验的工具指令直接显示为最终答案。
